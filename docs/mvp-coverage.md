# Соответствие MVP и ограничения прототипа

Основание: UBAS-KurganDev/docs, commit
d4d838879c6e054bd4acac22e2678dbfc8c8cf1a, mvp.md и критерии приёмки.
Позднее владелец согласовал ограничение охвата до 30 городов по привлекательности
и связности. Внутри выбранной области поиск завершается полностью; глобальная
оптимальность за её пределами не обещается. Охват возвращается в search_scope.
Это отдельное продуктовое решение поверх указанной ревизии требований.

| Группа критериев | Проверка |
| --- | --- |
| INPUT | Четыре HTTP-поля, фиксированный профиль, 30 включительных дней, местный сегодняшний день |
| ROUTE | Прямой, максимум одна остановка (уточнение владельца 06.11.2026), единые/отдельные билеты, UTC и местные границы, смена аэропорта |
| CITY | 11:59 / 12:00, оценки 59/60/61, каждая остановка, отсутствующая оценка = 0 |
| PRICE | Цена единого билета один раз, визовые расходы, неизвестные компоненты, RUB/FX, исходный fetched_at |
| RESULT | До 10 по известной цене, дубли, отсутствие квот, сравнение с независимым полным перебором |
| CARD | Массив остановок, расходы и неизвестность, аэропорты/время, багаж, отсутствие booking_url |
| FLOW | Нет частичных карточек, пустой завершённый поиск отличен от сбоя; worker не сохраняет partial |

Сценарии находятся в test_routing.py, test_planner_search.py,
test_direct_routes.py, test_api.py, test_worker.py, test_repository_wiring.py.
Это проверки синтетических данных, а не приёмка реального билетного источника.

## Открытые вопросы

- OPEN-01: временный tourism_threshold=60 явно выбран владельцем; калибровка впереди.
- OPEN-02: защитные тайм-ауты/бюджеты есть, реальный SLA не измерен.
- OPEN-03: поиск полон относительно данных и согласованного покрытия источников.
  Набор запросов ограничен выбранными городами; это ограничение явно согласовано.
  Мировая топология и реальные цены в репозиторий не добавлены.
- OPEN-04: курсы задаются явно; ROUND_HALF_UP до копеек по компонентам — временное
  техническое правило. Автоматический источник курса ещё не подключён.
- OPEN-05: временная политика — failed/search_incomplete без частичной выдачи
  при ограничении/ожидаемом сбое источника. Туристический источник даёт 0.
- OPEN-06: порт расчёта виз по всему маршруту есть; стандартный каталог не решает
  реальные правила повторных въездов и конечной страны. Неопределённые расходы
  маркируются, а не превращаются в бесплатные визы.
- OPEN-07: fetched_at сохраняется, повторной проверки цены нет. Срок устаревания
  кэшированных цен не установлен.

Число пассажиров и тариф проверяются на границе провайдера. Выбор минимального
тарифа с обязательными сборами, достоверные номера рейсов, условия багажа и охват
всех аэропортов — обязанности будущего адаптера. Синтетический провайдер не
подтверждает качество будущего скрапера.

Слово «синхронный» в MVP реализовано как ожидание всей выдачи без промежуточных
карточек. Существующие POST 202 и polling сохраняются. Отдельного изменения
трёхручечного транспорта в этом PR нет.

Схема очереди не меняется; конкурентность PostgreSQL следует проверять на
отдельной ubas_test_* базе. Если UBAS_TEST_DATABASE_URL не задан, эти проверки
пропускаются. CI остаётся только Ruff и mypy.
