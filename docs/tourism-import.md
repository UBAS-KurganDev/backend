# Сборщик туристической привлекательности

`ubas-import-cities` — офлайн-команда. Она собирает достопримечательности из
OpenTripMap, сохраняет JSON-снимок и обновляет оценки в существующем каталоге.
В пользовательском поиске внешних обращений к OpenTripMap нет: планнер читает
`SqliteCityRepository.get_many`. Топология и география остаются отдельными портами.
Импортер не меняет схему SQLite, PostgreSQL-очередь и контракт поиска маршрутов.

## Запуск

```shell
uv sync --locked
uv run --env-file .env ubas-import-cities --from-snapshot data/city_profiles.json --catalog var/topology-catalog.sqlite3
```

Включённый снимок — ранее собранные данные, а не свежая проверка источника.
Он покрывает только перечисленные в нём города. После импорта существующие API
и worker читают новые значения без пересоздания топологии. Уже завершённые задачи
не пересчитываются. Для проверки результата создайте новый поиск с новым ключом.

Для обновления из API задайте `UBAS_OPENTRIPMAP_API_KEY` в `.env`:

```shell
uv run --env-file .env ubas-import-cities --snapshot var/tourism.json --catalog var/topology-catalog.sqlite3
uv run --env-file .env ubas-import-cities --city ALA --city TAS --snapshot var/tourism.json --catalog var/topology-catalog.sqlite3
```

Список поддерживаемых городов находится в `TOP_CITIES`. `--limit` ограничивает
число запрашиваемых городов; его нельзя совмещать с `--city`. Эти режимы не меняют
шкалу оценки. При наличии снимка остальные записи сохраняются; свежие счётчики
заменяют старые. Ошибка отдельного города сохраняет его прежние данные и даёт
код завершения 1, хотя успешно собранные города импортируются. При полном отказе
источника ни снимок, ни каталог не меняются. Отсутствующий город не получает
выдуманную оценку. Прежние записи могут устаревать — проверяйте `fetched_at` в снимке.

## Временная формула оценки

Для точек в радиусе 10 км учитываются `interesting_places` с rate >= 3.
Точки с rate >= 4 имеют вес 3, остальные — вес 1:

```text
weighted = notable + 3 * landmarks
score = min(100, 100 * ln(1 + weighted) / ln(1 + 6000))
```

Это техническая калибровка `log1p_fixed_reference_v1`, а не подтверждённая
продуктовая модель. Опора 6000 близка к верхнему значению исходного снимка;
она фиксирована и не пересчитывается при добавлении городов. Ноль объектов даёт
ноль баллов. Порог MVP 60 достигается примерно при 184 взвешенных объектах.
Полнота OpenTripMap, радиус и плотность объектов влияют на результат: оценка
не доказывает, что в городе интересно провести два дня. Калибровку нужно проверить
на реальных городах с владельцем продукта. Изменение формулы требует новой версии
политики и явного пересчёта снимков.

В планнере оценка участвует в выборе до 30 городов и в фильтре остановок >=12 часов
с порогом 60. Итоговые маршруты по-прежнему сортируются по известной цене.

## Сохранность и ошибки

- Снимок заменяется атомарно после успешной сериализации. Запись в SQLite — отдельная
  атомарная транзакция; общей транзакции файла и БД нет. После ошибки БД повторите
  импорт сохранённого снимка через `--from-snapshot`.
- В существующем профиле обновляются только `tourism_score` и `profile_version`.
  Визы, отели, название, часовой пояс и направления остаются прежними. Новые города
  создаются без визовых данных; неизвестные расходы не становятся бесплатными.
- Снимки старого PR со шкалой 0–1 пересчитываются из исходных счётчиков по новой
  фиксированной формуле. `generated_at` старого снимка сохраняется как время
  исходного сбора в `fetched_at`. Новые снимки имеют `snapshot_version=2`.
- Неполная пагинация (6 полных страниц по 500 объектов) считается ошибкой города,
  а не достоверным числом достопримечательностей. Сетевые повторы ограничены;
  API-ключ не включается в сообщения ошибок.
- Чтение старых JSON-профилей каталога 0–1 остаётся совместимым. SQL-строк,
  новой ORM-схемы и aiosqlite не требуется.

## HTTP для фронта

- `GET /api/v1/cities?limit=100&min_tourism_score=60`: массив `CityProfile`,
  по убыванию оценки, при равенстве — IATA. `limit` 1–500, по умолчанию 100;
  `min_tourism_score` 0–100, по умолчанию 0.
- `GET /api/v1/cities/ALA`: профиль, 404 если отсутствует, 422 для неверного кода.
- Нет подключённого источника — 503. Ответы содержат `profile_version=2` и шкалу
  0–100. Это справочные оценки, не готовые предложения маршрутов.

HTTP зависит от `CityDirectory`, планнеру достаточно `CityRepository`. Реализация
выбирается обычным кодом в `runtime.py`; SQLite не входит в контракт портов.
