# Скрапер agent.ru

Адаптер работает как Python-модуль внутри процесса worker, реализует FlightProvider.
Отдельный сервис не нужен. FastAPI не запускает браузер, если встроенный worker
отключён. Подключение остаётся явным: runtime загружает указанную фабрику.
Реальные билеты не заменяют топологию, географию или привлекательность городов.

## Запуск

```shell
uv sync --locked
uv run --locked playwright install chromium
```

На Linux нужны системные зависимости Chromium:
`uv run --locked playwright install --with-deps chromium`.
Dockerfile устанавливает Chromium и зависимости при сборке, браузер работает от
пользователя ubas. Профили создаются Playwright временно; пакет доступен только
для чтения, каталоги внутри site-packages не создаются.

В .env:

```dotenv
UBAS_FLIGHT_PROVIDER_FACTORY=ubas_backend.agent_scraper.provider:create_flight_provider
UBAS_AGENT_HEADLESS=true
UBAS_AGENT_MAX_CONCURRENCY=2
UBAS_AGENT_TIMEOUT_SECONDS=60
UBAS_AGENT_CACHE_TTL_SECONDS=1800
UBAS_AGENT_CACHE_MAX_ENTRIES=128
UBAS_AGENT_MAX_RESPONSE_BATCHES=100
# Redis необязателен. Пустая переменная оставляет только память процесса.
UBAS_AGENT_REDIS_URL=
# Скопируйте config/planner.json в ./var/planner.json для Compose.
UBAS_PLANNER_CONFIG_PATH=./var/planner.json
```

Файл config/planner.json задаёт query_timeout_seconds=90. API и worker должны
использовать один файл. Бюджет отдельного запроса включает ожидание свободного
браузера и все пары аэропортов города; 90 секунд не гарантируют их завершение.
Общий лимит планировщика по умолчанию 240 секунд, worker — 300 секунд.
Подбор бюджетов под согласованные направления/даты и нагрузку остаётся задачей
эксплуатации; лимиты не отключаются ради успешного ответа.

Само приложение .env не читает: используйте `uv run --env-file .env ...`.
Для одиночной диагностики без очереди/каталога:

```shell
uv run --env-file .env python -m ubas_backend.agent_scraper --origin SVX --destination AYT --date 2027-01-15
```

Дата должна быть будущей и укладываться в горизонт источника. Команда выводит
нормализованный FlightSearchResult; это диагностика поставщика, а не топ-10
маршрутов планировщика. Обычный запуск API/worker описан в README.

В Compose переменные UBAS_AGENT_* передаются worker. Внешний Redis подключается
явным URL; localhost внутри контейнера означает сам контейнер, а не хост.
Redis не обязателен для запуска и не добавляется в Compose автоматически.

## Контракт и дата

Планировщик передаёт коды **городов**, диапазон дат, один взрослый, RUB и предел
числа предложений. Поставщик раскрывает город в поддерживаемые аэропорты из
airports.py, например MOW → SVO/DME/VKO/ZIA, TYO → HND/NRT и GOI → GOI/GOX.
BAK — город Баку, GYD — его аэропорт. Старый TSE распознаётся при разборе,
но для новых запросов Астаны используется только NQZ. Ответы аэропортов снова
содержат город IATA и аэропорт IATA отдельно.

Источник ищет один день. На широкий диапазон адаптер возвращает complete=false,
не выполняя браузерный поиск. TicketSearch делит его на непересекающиеся части
до одного дня. Пустой неполный ответ тоже делится: середина диапазона больше не
подменяет всё окно. Для этого refine_date_ranges должен оставаться true.

URL agent.ru содержит DDMM без года. Адаптер разрешает только ближайшее
наступление этой даты и дополнительно проверяет календарную дату каждого билета.
Далёкий год — ошибка источника; прошедший день из расширенного окна планировщика
возвращает пустой результат, поскольку такие вылеты уже не подходят.
Неверная дата в ответе никогда не превращается в успешное отсутствие билетов.

## Как устроен реальный ответ

Формат проверен живым поиском SVX → AYT 18.11.2026, выполненным 04.11.2026.
Обезличенная фикстура tests/fixtures/agent-offers.json сохраняет структуру и
публичные поля рейсов, заменяет идентификаторы поиска/покупки и удаляет прочие
служебные поля. Это исторический пример, не актуальное ценовое предложение.

Структура:

```text
offers / ow_offers
  группа перевозчика
    offers: группы вариантов
      segments: самостоятельные варианты покупки
        buy_id
        price: цена именно этого билета
        price_details: состав пассажиров
        flights_info: последовательность реальных перелётов
```

Один элемент segments превращается в один TicketOffer. Все его flights_info
остаются внутри одного билета (до четырёх перелётов). Цена price учитывается
один раз. min_price группы не переносится на варианты; отсутствие price
обозначается неизвестным расходом. Невалидная цена — ошибка контракта.

Локальные дата и время каждого перелёта переводятся через IANA-зону аэропорта.
Поля *_timestamp и фиксированный GMT-сдвиг источника не используются: в
наблюдённом ответе они расходились с локальным расписанием и длительностью.
Отсутствующие аэропорт, дата, номер рейса или перевозчик не выдумываются.
Неоднозначное/несуществующее время на переходе DST отклоняется с неполнотой.

Сохраняются багажные условия по каждому перелёту. Неизвестный формат багажа
остаётся текстом, логическое наличие — null. buy_id не доказывает гарантию
перевозчика: protected_connection=false, пока нет подтверждённого признака.
Booking URL не создаётся. ID билета — хеш служебного ID и позиции варианта;
дубликаты вариантов остаются отдельными наблюдениями.

## Полнота, кэш и отмена

Браузер открывается без общего постоянного профиля. Ответы обрабатываются
последовательно, без незарегистрированных асинхронных callback-задач.
Проверяются request_id и цепочка next_token. InProcess содержит очередную порцию,
Ready завершает поиск и тоже может содержать билеты. Точный повтор страницы
не добавляется дважды; разные варианты в самой странице не дедуплицируются.

Таймаут не превращает InProcess в Ready. Ошибка HTTP, разрыв цепочки, превышение
100 ответов или 20 MB данных — FlightProviderError. Ошибка разбора варианта или
обрезка по query.limit — complete=false. Планировщик завершает такой запрос как
failed/search_incomplete; частичные карточки не показываются.

Кэш содержит полную исходную выдачу и время её наблюдения. Ключ включает оба
аэропорта, полную дату с годом, пассажиров, класс, валюту и версию формата.
fetched_at — время первого ответа этого поиска; чтение из памяти или Redis
его не меняет. Это время получения нашим адаптером, не гарантия свежести
внутреннего кэша agent.ru. Выдуманный expires_at больше не задаётся.
TTL 1800 секунд — настройка хранения, а не согласованный продуктовый срок
достоверности цены (OPEN-07 остаётся открытым).

Одинаковые запросы внутри процесса разделяют один расчёт. Ожидатель может
отмениться, не отменяя владельца. Отмена владельца закрывает его браузер;
оставшийся ожидающий запрос может начать новый поиск. Отмена всего планирования
распространяется через TaskGroup на все дочерние поиски. Общий семафор сервиса
ограничивает браузеры во всех заданиях одного worker. Между процессами Redis
делит результаты, но не обеспечивает распределённый single-flight.

Redis используется через async I/O с короткими сетевыми таймаутами.
При его недоступности остаётся ограниченный кэш памяти. Runtime закрывает
клиент после остановки worker. Не сохраняются незавершённые ответы.

## Каталог и ограничения интеграции

airports.py — небольшой явный справочник покрытия, не мировая база аэропортов.
Неизвестный город — ошибка; неизвестный аэропорт в билете делает поиск неполным.
Наличие города в справочнике не доказывает полноту его покрытия в мире.
Перед расширением географии нужно проверить состав аэропортов и IANA-зоны,
добавить их в справочник или заменить эту зависимость полноценным каталогом.
Состав и соответствия сверяются с публичным справочником
[Travelpayouts](https://api.travelpayouts.com/data/en/airports.json), который также
использует сборщик топологии в отдельном PR №4. Слияние скрапера само по себе
не подключает этот сборщик и не расширяет статический справочник до всего мира.

Скрапер получает варианты текущей выдачи agent.ru; отдельные семейства тарифов,
технические остановки, нестандартные виды транспорта и другие формы ответа
не считаются автоматически поддержанными. Новые формы требуют примера источника
и регрессионной проверки. Источник может менять API, ограничивать запросы или
не завершать поиск. Нет обхода CAPTCHA или иных ограничений доступа.

Опциональная команда создаёт **новый** иллюстративный каталог:

```shell
uv run --locked python -m ubas_backend.agent_scraper.catalog --catalog ./var/agent-example.sqlite3
```

Она не читает UBAS_CATALOG_PATH, не перезаписывает существующий файл и не
подставляет бесплатные визы/отели или вымышленные положительные оценки.
Оценки равны 0, визы отсутствуют; связи только иллюстрируют топологию. Поэтому
остановки от 12 часов без реального источника привлекательности будут отсеяны.
Для рабочей выдачи нужны отдельно проверенные топология, профили и география.

Изменений трёх HTTP-ручек и схемы PostgreSQL нет. Используется контракт результата
версии 2 из master. CI остаётся Ruff + mypy. Регрессии скрапера локально:

```shell
uv run --locked python -m unittest discover -s tests -p test_agent_scraper.py -v
```
