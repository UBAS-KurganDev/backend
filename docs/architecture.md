# Устройство UBAS Backend

Нормативный источник — [репозиторий docs](https://github.com/UBAS-KurganDev/docs).
Текущая реализация ориентируется на ревизию
d4d838879c6e054bd4acac22e2678dbfc8c8cf1a. Временный T=60 выбран владельцем проекта.

## Поток выполнения

FastAPI → QueryManager → PostgreSQL-очередь → QueryWorker → RoutePlanner.
API и worker — отдельные процессы; в локальном режиме worker можно встроить.
Клиент видит карточки только после завершения всего поиска. Идемпотентность,
аренда и повторы сохраняются; незавершённый поиск не публикуется как результат.

Планировщик получает топологию и профили через независимые протоколы, собирает
билеты, строит временной индекс и находит десятку по цене методом ветвей и границ.
Перед билетным поиском выбираются до max_hubs городов по привлекательности и
связности. Область записывается в search_scope; полнота относится к этой области.
Единый билет — атомарная покупка с несколькими рейсами. Цена учитывается один раз.
Допустимо до трёх остановок. Привлекательность — фильтр только от 12 часов.
Никаких рейтингов дневного времени, проверки въезда и квот выдачи нет.

## Модули

| Модуль routing | Ответственность |
| --- | --- |
| schemas.py | Запросы, билеты, профили, остановки и результат |
| config.py | Порог привлекательности, курсы и защитные лимиты |
| ports.py | Источники билетов, топологии, профилей, географии и визовых расходов |
| policy.py | Четырёхполевой MVP, окно 30 дней, местная текущая дата |
| hubs.py, topology.py | Прямые/обратные границы числа перелётов; fallback обход по слоям |
| offers.py | Конкурентное получение билетов и разбиение неполных диапазонов дат |
| validation.py | Чистая проверка контракта предложения |
| costs.py | Конвертация известных расходов и стандартный визовый адаптер |
| candidates.py | Проверка остановок/дат и сборка карточки |
| search.py | Временной индекс, нижние границы и best-first поиск |
| selection.py | Десятка по цене без дедупликации |
| planner.py | Координация, тайм-аут, запрет частичной выдачи |
| diagnostics.py | Причины отсева и признаки незавершённого поиска |
| storage.py, catalog_models.py | SQLite на SQLAlchemy, отдельные читающие репозитории |
| demo.py | Явно вымышленные данные для локального запуска |

Старые daytime.py и scoring.py удалены вместе с ненужной эвристикой.
У источников обычная передача зависимостей в конструктор, без реестров плагинов.
Реализации собираются в runtime.py. Хранилища не проникают в доменные модели.

Пакет topology — отдельный сборщик направлений и географии: async HTTP, проверка
снимка, затем атомарный импорт через SqliteCatalog. Он не выполняется внутри
планирования. Источники, охват и команда запуска — [topology.md](topology.md).

## Хранилища и конкурентность

PostgreSQL хранит запросы, ключи, аренды и JSON результатов. Каждая операция
использует отдельную короткую AsyncSession и SQLAlchemy ORM/Core.
SQL-строк нет. Поиск билетов выполняется вне транзакций.
SKIP LOCKED и условные обновления с lease-токеном сохраняют гарантии очереди.

SQLite содержит направленные связи и профили. Источники топологии,
привлекательности и географии можно заменять отдельно; отсутствие оценки
не должно стирать географию города. SQLite-чтение выполняется через to_thread,
сетевые провайдеры должны использовать отменяемый async I/O.
