# UBAS Backend: правила работы с проектом

## Приоритет требований

Нормативный источник — https://github.com/UBAS-KurganDev/docs:
mvp.md и «Критерии приёмки MVP.md». Реализация согласована с ревизией
d4d838879c6e054bd4acac22e2678dbfc8c8cf1a. При конфликте старых локальных описаний
руководствуйтесь репозиторием docs. Владелец проекта явно выбрал временный T=60.
Дополнительно владелец согласовал ограниченный охват: до max_hubs (по умолчанию 30)
городов по привлекательности, затем связности. Это явное уточнение полноты поиска.

## Границы MVP

- Ввод: города IATA отправления/назначения и две даты. Окно до 30 дней включительно.
- Фиксированы один взрослый, эконом, гражданство РФ, обычный загранпаспорт
  без иностранных виз и ВНЖ. Нет авторизации, покупки, booking links или отелей.
- Ищем прямые рейсы и маршруты до трёх промежуточных остановок.
- Единые и отдельные билеты поддерживаются; цена единого билета учитывается один раз.
- Вылет/конечное прибытие укладываются в местные даты аэропортов. Начало не в прошлом
  по местному календарю города отправления. Интервалы и хронология считаются в UTC.
- Любая строго положительная пересадка допустима. Нет лимита 72 часа, буферов,
  требования дневного времени или выхода в город. Смена аэропорта разрешена.
- Для каждой остановки >=12 часов нужна оценка >=T по шкале 0–100.
  Нет ответа источника привлекательности — оценка 0; короткую остановку это не исключает.
- Выдача — до 10 по возрастанию суммы известных билетов и виз в RUB.
  Дубли сохраняются, квот и дополнительных критериев рейтинга нет.
- Неизвестный обязательный расход не исключает маршрут: известная сумма плюс
  явная пометка неполной стоимости. Отели и переезды не включаются.
- Не проверяем возможность въезда/транзита/получения визы. Считаем расходы.
- Не перепроверяем цену перед показом; fetched_at сохраняется из источника.
- Только завершённая выдача. Ошибка/лимит поиска — не успешное отсутствие маршрутов.
- Выбор до max_hubs городов — согласованный охват, не ошибка. Возвращайте search_scope;
  complete относится к выбранным парам/датам. Ошибки источника и исчерпание бюджетов
  внутри области остаются search_incomplete. Глобальную оптимальность не обещайте.
- Реальный провайдер подключается отдельно; routing/demo.py содержит вымышленные данные.
  agent_scraper — адаптер agent.ru, его покрытие и ограничения описаны отдельно.

## Стек и стиль

Python 3.14+, FastAPI, Pydantic 2, SQLAlchemy ORM/Core, Alembic, uv.
При изменении зависимостей обновляйте pyproject.toml и uv.lock.
Соблюдайте строгий mypy и Ruff; не отключайте проверки ради CI.

Короткие функции, явные зависимости и разделение ответственности.
Доменные проверки возвращают результат/типизированную причину; статистика отдельно.
Не вводите универсальные фабрики и классы на каждую проверку без необходимости.
Топология и привлекательность не зависят от SQLite: реализации передаются в
runtime.create_planner обычным кодом. Для географии есть отдельный порт, чтобы
отказ туристического скрипта не ломал проверку местного дня.
Не храните секреты в исходниках, документации, логах или фикстурах.

## Работа с БД

- Не добавляйте SQL-строки, text(), exec_driver_sql(), запросы через драйвер
  или .sql-миграции. Используйте SQLAlchemy ORM/Core и Alembic operations.
- asyncpg — только драйвер SQLAlchemy. ORM-модели не выходят в API/планировщик.
- Короткая сессия на операцию; не делите AsyncSession между конкурентными задачами.
  Не держите транзакцию во время поиска билетов.
- Конкурентность обеспечивается ограничениями БД, транзакциями и условными
  обновлениями, а не локальными Python-lock.
- Схему меняйте новой Alembic-ревизией; не переписывайте применённые миграции.
  Проверяйте включение ревизий в wheel и работу вне checkout.
- Сохраняйте UUID, результаты и связи ключей. Для несовместимых изменений
  документируйте остановку и обновление процессов.
- SQLite-каталог и PostgreSQL-очередь — отдельные хранилища.
- SqliteCatalog только создаёт/наполняет; читающие репозитории отдельные, read-only.
- Сборщик топологии заменяет только связи явно выбранных исходных городов,
  одной транзакцией после загрузки всех их аэропортов. Профили не перезаписываются.
  Ошибка источника не равна пустой выдаче. Сохраняйте JSON-снимок и атрибуцию.
- Старый SQLite JSON без profile_version использует шкалу 0–1, новая версия 2 —
  0–100. Нормализация старых данных выполняется при чтении без перезаписи файла.

## Очередь

- Один клиентский ключ связан с прежним телом и запросом; другое тело — 409.
- Все ключи сохраняются, даже если активные одинаковые запросы объединены.
- Активные дубликаты запрещены уникальным индексом. Новый ключ после завершения
  создаёт поиск; старый возвращает прежнюю задачу.
- Захват — with_for_update(skip_locked=True).
- Запись результата и продление требуют актуального токена и неистёкшей аренды.
  Время аренды считается по часам БД.
- Потеря аренды отменяет расчёт и дочерние поиски. Ошибка БД не убивает слот навсегда.
- Лимит попыток хранится в задаче. Неверный ввод не повторяется.
- At-least-once: внешние вызовы могут повторяться; exactly-once не обещайте.
- Незавершённая выдача не становится completed. Временная политика MVP:
  failed/search_incomplete без частичных карточек.
- Исторические результаты читаются с schema_version=1, новые имеют 2.
  Старые поля и JSON сохраняются для чтения; не пересчитывайте историю.

## Поиск

- API и worker читают одну PlannerConfig через UBAS_PLANNER_CONFIG_PATH.
- Цена — Decimal. Конвертация по явным rub_rates, неизвестный курс — неизвестный расход.
  Не подставляйте вымышленные курсы или бесплатные визы.
- VisaCostResolver получает весь маршрут; не складывайте автоматически одинаковые
  визы при повторном посещении страны. Политика OPEN-06 ещё не согласована.
- Ограничивайте города, предложения, вызовы, кандидатов, очередь и время поиска.
- Async I/O провайдера отменяемый; синхронный код не блокирует event loop.
- Сохраняйте причины отсева и предупреждения. Нет профиля — score=0, не исключение города.
- Отсечение возможно только по доказанной нижней границе цены и десяти реальным
  результатам. Неизвестные расходы = 0 в границе; визовые расходы из неё исключены.
- При изменении поиска сравнивайте с независимым полным перебором малых наборов.
  Доказанное отсечение сохраняет полноту; бюджет с перспективными ветвями — ошибка
  завершения поиска, не готовая выдача.
- При уточнении дат заменяйте родительский ответ дочерними непересекающимися
  диапазонами. Реальные дубли источника сохраняются.

## Запуск и проверки

```shell
uv sync --locked
uv run --env-file .env ubas-migrate
uv run --env-file .env ubas-api
uv run --env-file .env ubas-worker
```

.env не читается автоматически. API и worker — отдельные процессы;
UBAS_EMBEDDED_WORKER=true только для локального режима.
API теперь тоже требует каталог с географией исходных городов.
Для демонстрации явно создайте отдельный каталог по README.

Перед завершением изменений:

```shell
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked python -m unittest discover -s tests -v
```

PostgreSQL-проверки требуют UBAS_TEST_DATABASE_URL и отдельную ubas_test_* БД:
они очищают очередь. Без переменной пропускаются. Не подтверждайте
конкурентность PostgreSQL только SQLite/mock.
При изменении упаковки/миграций выполняйте uv build --no-sources и проверки
миграций из пакета/обновления схемы. CI — только Ruff и mypy, без тестового шага.
Различайте выполненные проверки, пропуски и ограничения окружения.
